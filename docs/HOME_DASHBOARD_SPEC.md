# مشخصات صفحه اول مدیریتی سامانه تحلیل حساسیت

## 1. هدف
صفحه اول سامانه تحلیل حساسیت علاوه بر دسترسی به انواع سناریو، باید یک نمای مدیریتی و تحلیلی از وضعیت جاری درجه‌بندی شعب در Data Scope کاربر ارائه کند.

اطلاعات این صفحه باید از **Database داشبورد درجه‌بندی شعب** خوانده شود و سامانه تحلیل حساسیت نباید رتبه، درجه یا امتیاز رسمی را مستقلاً دوباره محاسبه کند.

## 2. اعمال Data Scope
تمام KPIها، نمودارها و جداول صفحه اول باید پس از اعمال Data Scope کاربر تولید شوند:

- کاربر شعبه: فقط شعبه خود کاربر
- کاربر منطقه: فقط شعب زیرمجموعه منطقه
- کاربر ستادی: کل شبکه شعب

Scenario Ownership مستقل است و تعداد سناریوهای ذخیره‌شده فقط شامل سناریوهای خود کاربر است.

## 3. بخش‌های صفحه

### 3.1 KPIهای اصلی
حداقل KPIهای زیر نمایش داده شوند:
- تعداد شعب در Scope
- تعداد مناطق در Scope
- میانگین امتیاز نهایی
- دوره مبنای فعال
- تعداد سناریوهای ذخیره‌شده کاربر

در Scope شعبه، KPI «تعداد مناطق» می‌تواند حذف یا به اطلاعات شعبه تبدیل شود.

### 3.2 توزیع درجات
نمایش تعداد شعب به تفکیک Grade.

داده از فیلد `grade` در خروجی رسمی Dashboard DB دریافت می‌شود.

### 3.3 وضعیت مناطق
برای Scopeهای منطقه و ستاد:
- تعداد شعب هر منطقه
- میانگین `final_score` شعب هر منطقه

این بخش صرفاً Aggregation روی خروجی رسمی است و رتبه جدیدی برای مناطق تولید نمی‌کند، مگر اینکه Database داشبورد رتبه رسمی منطقه را به‌صورت مستقل ارائه کند.

### 3.4 نمای شاخص‌های اصلی
برای هر یک از 8 شاخص، میانگین `normalized_score` شعب داخل Scope نمایش داده شود.

شاخص‌ها:
- میانگین سپرده‌ها
- تعداد سپرده‌ها
- میانگین تسهیلات
- تعداد تسهیلات
- میانگین تعهدات
- تعداد تعهدات
- حجم عملیات
- سود و زیان

این نمودار برای مقایسه وضعیت نسبی شاخص‌ها در Scope کاربر است و Weight یا Score جدید محاسبه نمی‌کند.

### 3.5 تغییر رتبه نسبت به دوره قبل
در صورتی که Dashboard DB مقادیر معتبر `previous_rank` و `rank_change` را ارائه کند:
- بیشترین بهبود رتبه
- بیشترین افت رتبه
- تعداد شعب با بهبود/افت/بدون تغییر

اگر داده دوره قبل وجود نداشته باشد، این بخش نمایش داده نمی‌شود.

### 3.6 ورود به تحلیل سناریو
کارت‌های سه نوع سناریوی موجود در صفحه اول حفظ می‌شوند:
- تحلیل تک‌شعبه‌ای
- تحلیل چندشعبه‌ای
- Target Rank

نمای مدیریتی باید مکمل این کارت‌ها باشد و جای Workflow سناریو را نگیرد.

## 4. منابع داده
| بخش | منبع |
|---|---|
| Authentication | AD |
| Data Scope | HRM + Hierarchy موجود در Dashboard DB |
| شعب، مناطق، امتیاز، رتبه، Grade | Dashboard DB |
| شاخص‌ها و `normalized_score` | Dashboard DB |
| تاریخچه و `rank_change` | Dashboard DB |
| سناریوهای ذخیره‌شده | Database سامانه تحلیل حساسیت |

## 5. قواعد محاسباتی صفحه
محاسبات مجاز در صفحه اول فقط Aggregation و Presentation هستند، مانند:
- Count
- Mean
- Group By
- Sort
- Filter

محاسبه مجدد موارد زیر در صفحه اول مجاز نیست:
- Normalization
- Weighting
- Final Score
- Rank
- Grade

این مقادیر باید مستقیماً از خروجی رسمی Dashboard DB دریافت شوند.

## 6. حالت نبود داده
اگر یک Data Set مانند تاریخچه رتبه موجود نباشد، UI باید آن بخش را حذف یا پیام «اطلاعات دوره قبل در دسترس نیست» نمایش دهد و مقدار فرضی تولید نکند.

## 7. معیار پذیرش
- تمام اطلاعات صفحه متناسب با Data Scope کاربر باشد.
- تعداد سناریوهای نمایش‌داده‌شده فقط مربوط به کاربر جاری باشد.
- اعداد رسمی رتبه/درجه/امتیاز با Dashboard اصلی بانک یکسان باشند.
- هیچ Ranking موازی داخل سامانه تحلیل حساسیت ایجاد نشود.
